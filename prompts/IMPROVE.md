# 남은 시간 안에서 수정과 검증을 반복하기

[시험 첫 화면](../README.md) · [전체 문서 지도](../docs/INDEX.md)

제출 확정 전에만 적용한다. 기존 작업과 같은 Codex 대화에서 사용하며, 새 프로젝트로 다시 만들라는 요청이 아니다. 첫 실행 결과가 나온 뒤에도 실제 요구 충족·사용성·정확성을 점검하며 개선하기 위한 지침이다. 기본 진행은 [SCENARIO](SCENARIO.md)를 따르고 이 문서의 기준을 추가한다.

## Codex가 적용할 개선 순서

1. **좋은 결과의 기준을 먼저 정한다.** 실제 README의 필수조건, 참가자 피드백, 기존 업무 답변을 관찰 가능한 기준으로 바꾼다. 예: “화면을 예쁘게”는 임의로 통과 처리하지 말고 정보 우선순위·글자 가독성·표 잘림·상태 구분 같은 항목으로 구체화한다. 취향에 따라 크게 달라지는 선택만 짧게 확인하고 확정된 수정은 계속한다.
2. **현재 결과에서 큰 문제를 찾는다.** 실행 불가·잘못된 결과·필수 누락 → 핵심 사용 흐름 → 가독성·표현 → 부가 개선 순서로 본다. 실제 과제에서 디자인·표현을 필수로 요구하면 필수조건으로 다룬다. 자신이 만든 테스트 통과만으로 사용자 만족이나 전체 요구 충족을 선언하지 않는다.
3. **한 묶음씩 고치고 검증한다.** 개선할 문제, 바뀌어야 할 동작, 확인 방법을 짧게 정한 뒤 구현한다. 관련 테스트·빌드·함수/API 실행을 실제 수행하고, 실패하면 원인을 고쳐 같은 입력과 정상 사례를 다시 확인한다. 이미 통과한 핵심 동작이 깨졌는지도 살핀다. 변경·새 위험·실패가 없으면 같은 검사를 의미 없이 반복하지 않는다.
4. **현재 결과를 다시 평가한다.** 남은 요구·피드백과 비교해 효과가 큰 다음 개선을 고른다. 이미 완료한 기능을 또 만들거나 설명만 반복하지 않는다. 연속 시도에 진전이 없으면 원인 가설을 바꾸거나 더 작은 재현으로 좁힌다. 문제와 무관한 전면 재작성·스택 교체·도구 추가로 빠지지 않는다.
5. **시간 또는 완료 기준에 맞춰 마친다.** 필수조건·합의한 품질 기준이 충족되고 유의미한 개선 근거가 없으면 결과와 한계를 정리한다. 시간이 남았다는 이유만으로 계속 바꾸지 않는다. 개선 중단 시각이면 새 개선을 멈추고 최종 관련 검사·문서·저장·제출 안내로 전환한다. 필수 실패가 남으면 완료라고 하지 말고 영향과 가능한 최소 대응을 알린다.

이 과정은 같은 Codex가 조사·수정·검증 역할을 순서대로 수행한다. 별도 에이전트·병렬 프로세스·추가 모델을 자동 실행하는 기능이 아니다. 허용된 실행 권한 안에서 매번 “계속할까요?”를 묻지 않고 진행하되, 실제 승인 창·필수 업무 결정이 필요하면 그 부분을 알린다.

## 시간은 화면과 실제 시계로 확인한다

- 참가자가 알려 준 **작업 타이머, 현재 시각·시간대, 개선 중단 시각**을 구분한다. 응시 화면의 타이머를 직접 읽을 수 있다고 가정하지 않는다. 마감 정보가 없으면 이를 짧게 요청하면서 독립된 작은 수정·검사는 진행한다. 시간을 모른 채 장시간 반복 작업을 약속하지 않는다.
- 각 개선 묶음 시작 전에 가능한 실행 환경 시계로 경과 시간을 확인한다. 현재 타이머의 정확한 값은 참가자가 갱신한 안내를 우선한다. 명령·대형 분석의 실행 시간도 남은 작업 시간 안으로 제한한다.
- 개선 중단은 **직접 제출을 시작할 시각보다 앞**으로 잡아 최종 검증·문서·저장 여유를 남긴다. 예를 들어 개선 중단 → 5분간 최종 정리 → 작업 종료 10분 전 직접 제출 시작은 키트의 계획 예다. 실제로 필요한 검사 시간에 따라 더 일찍 전환한다.
- 2026-11-04의 전체 마감은 23:00 KST다. 서술형 30분·질문 준비 대기·마지막 처리를 남겨야 하므로 늦게 시작했다면 작업 타이머만 보고 계획하지 않는다. [시간 배분 예](../docs/DAY-PLAN.md)
- 프롬프트와 `/goal`은 시험 타이머 연동·정시 자동 차단 기능이 아니다. 참가자가 화면의 시간을 확인하고 종료 시점에 진행 중인 AI 작업을 멈춘다. 제출 확정 후에는 대기 중에도 AI를 사용하지 않는다.

## 기능 검사와 본인 화면 확인을 구분한다

코드·데이터·API·빌드 검증은 허용된 로컬 도구로 자동 수행한다. UI 자동 조작은 하지 않는다. 웹 결과물이 있으면 서버의 실제 포트·경로와 사람이 할 핵심 동작을 짧게 제시한다. 참가자가 Probe Browser에서 직접 확인한 피드백으로 수정하며, 보지 않은 화면을 시각 검증 완료라고 기록하지 않는다. 수동 결과를 기다리는 동안 독립적인 코드·데이터·문서 검사는 계속한다.

각 묶음이 끝나면 **고친 점 / 이유 / 방법 / 실제 확인 / 남은 가장 큰 문제**를 짧게 알린다. 기존 기록에 근거만 누적하고 전체 보고서를 매번 다시 만들지 않는다.

## 그대로 보낼 요청문

빈칸은 실제 화면의 값과 원하는 품질로 바꾼다. 최초 시작 요청 뒤에 보내거나, 아래처럼 두 지침을 함께 읽게 해도 된다.

```text
아직 제출 확정 전이야. .cofa-kit/prompts/SCENARIO.md와
.cofa-kit/prompts/IMPROVE.md를 읽고 적용해 줘.
현재 시각은 __:__ KST, 화면의 작업 남은 시간은 __분이야.
개선은 __:__ KST에 멈추고 최종 검증·문서·저장·제출 안내로 전환해 줘.
중요한 품질 기준은 [실제 원하는 기능·사용성·표현]이야.
첫 구현에서 끝내지 말고 요구사항 점검 → 중요한 문제 수정 → 실제 검증 → 회귀 확인을 반복해 줘.
검증된 기존 기능과 내 변경을 보존하고, 매번 계속할지 묻지 말고 가능한 작업을 이어가 줘.
기준을 충족했거나 더 고칠 근거가 없으면 억지로 바꾸지 말고 완료·한계를 정리해 줘.
Browser 확인과 제출은 내가 할게. 필요한 수동 확인을 알려 주고 독립된 검사는 계속해 줘.
매 묶음마다 무엇을 왜 어떻게 고쳤고 무엇을 확인했는지 쉬운 말로 짧게 알려 줘.
```

`IMPROVE.md`의 실제 위치는 `.cofa-kit/prompts/IMPROVE.md`다. 받은 폴더 이름이 다르면 실제 경로를 쓴다.

## 결과가 마음에 들지 않을 때

같은 대화에 **관찰한 문제 + 원하는 결과 + 유지할 것 + 남은 시간**을 보낸다. “알아서 고급스럽게”만 전달하면 원하는 방향과 또 달라질 수 있다. 아래 항목은 예시이며 과제에 없는 기능을 추가하라는 뜻이 아니다.

```text
아직 제출 확정 전이야. 기존 작업을 이어서 수정해 줘.
마음에 안 드는 점: [예: 중요한 결과가 아래에 묻히고 표 글자가 작음].
원하는 결과: [예: 핵심 결과를 먼저 보여 주고 현재 화면에서 표를 읽기 쉽게].
유지할 것: [예: 계산 기준·필터 동작·입력 파일 형식].
현재 시각은 __:__ KST, 작업 남은 시간은 __분, 개선 중단 시각은 __:__ KST야.
이를 확인 가능한 기준으로 바꾸고 실제 수정까지 진행해 줘.
수정 후 관련 검사와 기존 핵심 동작을 다시 확인하고, 내가 Browser에서 볼 항목도 알려 줘.
```

## `/goal`을 지원하면 선택적으로 사용

OpenAI 공식 문서는 대화형 Codex CLI의 `/goal <목표>`와 `/goal edit`, `/goal pause`, `/goal resume`, `/goal clear`를 안내한다. 목표는 현재 대화에 유지되며 같은 대화의 후속 메시지로 방향을 바꿀 수 있다. 권한·승인 범위는 넓어지지 않는다. [명령](https://learn.chatgpt.com/docs/developer-commands#set-or-view-a-task-goal-with-goal), [목표로 계속 작업하기](https://learn.chatgpt.com/docs/long-running-work)

**Cofa의 실제 CLI 버전에서 지원하는지는 별도 확인한다.** Codex 입력칸에 `/`를 입력해 목록에 `goal`이 있는지 본다. 일반 셸 명령이 아니며, `codex --help`에 안 나온다는 이유만으로 미지원이라고 판단하지 않는다. 목록에 없으면 위 일반 요청문을 사용한다. 시험 중 CLI 업데이트·설정 변경·외부 반복 실행기로 기능을 억지로 추가하지 않는다.

지원한다면 실제 개선 중단 시각을 채워 다음처럼 목표를 시작한다. 목표가 이미 있으면 `/goal edit` 또는 같은 대화의 피드백으로 기존 목표를 조정한다.

```text
/goal .cofa-kit/prompts/SCENARIO.md와 .cofa-kit/prompts/IMPROVE.md를 적용해 실제 필수조건과 내가 정한 품질 기준을 충족하도록 수정·검증하라. __:__ KST에 개선을 멈추고 최종 검증·제출 준비를 완료하라. 화면·제출은 내가 직접 하며 제출 확정 후 AI 작업을 중단한다.
```

멈춰야 할 때는 지원되는 `/goal pause` 또는 화면의 중단 기능으로 진행 중인 작업을 멈춘다. 다시 계속할 때만 `/goal resume`을 쓴다. 서버·모든 터미널을 종료하는 명령을 목표 일시정지와 혼동하지 않는다. 실제 승인·결정 대기, 환경 오류, 모델의 조기 완료는 여전히 생길 수 있다. 일반 요청문에는 여러 턴에 걸친 자동 재개를 보장하는 기능이 없으므로 중간에 답변만 하고 멈췄다면 현재 결과·시간을 알려 같은 대화에서 계속 요청한다.
