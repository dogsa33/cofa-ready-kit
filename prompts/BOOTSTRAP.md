# 통합 시작: 목표·스킬·MCP·플러그인 준비 후 실제 과제 진행

[첫 화면](../README.md) · [진행 지침](SCENARIO.md) · [반복 개선](IMPROVE.md)

README의 통합 요청을 받은 제공 Codex가 읽는다. 제출 확정 전용이며, 참가자가 요청한 공개 키트의 설정 준비·지원되는 키트 플러그인 설치·실제 연결 확인을 수행한 뒤 과제 구현과 검증을 계속한다. 이 파일을 읽었다는 사실만으로 Goal·스킬 등록·MCP 연결·플러그인 로드를 완료했다고 말하지 않는다.

## 1. 실제 과제와 작업 시간을 먼저 확인

현재 위치, 실제 과제 README·AGENTS.md, 기존 코드·제출 조건을 읽는다. 작업 폴더는 실제 과제 루트로 유지하며 `.cofa-kit` 내부를 과제 루트로 바꾸지 않는다. 키트 README·examples는 문제나 답안이 아니다. 사용자 수정과 원래 파일을 보존한다.

[SCENARIO.md](SCENARIO.md)와 [IMPROVE.md](IMPROVE.md)를 적용한다. 필요한 SKILL.md만 실제 경로에서 직접 읽는다. 설치나 MCP 연결을 기다려야 스킬을 읽을 수 있는 것은 아니다.

화면의 작업 남은 시간·현재 시각·개선 중단 시각을 이미 전달받았으면 재사용한다. 모르면 한 번의 짧은 질문으로 확인하며 독립적인 요구사항·파일 점검은 계속한다. 시험 타이머를 볼 수 있다고 가정하거나 시간을 지어내지 않는다. 개선 중단은 최종 관련 검사·문서·저장·직접 제출 시간을 남겨 잡고, 23:00 전체 마감에는 서술형·질문 준비·마지막 처리까지 포함한다. [시간 계획](../docs/DAY-PLAN.md)

준비에 장시간을 쓰지 않는다. 2분 안팎을 설정 점검의 기본 예산으로 삼고 실제 남은 시간에 맞춰 더 줄인다. 이미 확인한 연결을 매번 다시 검사하지 않는다. 설정이 막혀도 가능한 기존 도구로 과제를 진행하며 실패·남은 수동 조치만 알린다.

## 2. Goal 상태를 사실대로 확인

- 참가자가 `/goal`로 시작했고 실제 목표 상태를 조회할 수 있으면 현재 목표·진행 상태를 확인한다. 이미 있는 목표를 지우거나 중복 생성하지 않는다.
- 일반 요청으로 들어왔더라도 목표 설정을 명시적으로 요청했고, 현재 도구 목록에 목표 조회·설정 기능이 실제로 있으면 지원되는 방식으로 설정하고 결과를 확인한다. 도구·명령을 추측해 만들어내지 않는다.
- CLI의 `/goal`은 사람이 Codex 입력칸에 넣는 명령이다. 셸에서 `/goal`을 실행하거나, 파일에 목표를 써 놓고 Goal이 활성화됐다고 보고하지 않는다. `codex --help`만으로 slash 명령 지원을 판정하지 않는다.
- 실제 상태를 확인할 수 없으면 `목표 지침 적용 / Goal 활성화는 미확인`으로 표시한다. 현재 과제를 계속하며 필요한 경우 참가자에게 `/` 목록에서 `goal`을 확인하도록 한 번 안내한다. `/goal`이 없으면 일반 요청으로 반복 개선하되 여러 턴 자동 재개를 보장하지 않는다.

Goal이 권한·승인·시험 타이머를 바꾸지는 않는다. `/goal pause`는 지원되는 입력칸에서 사용하며, 서버 등 모든 프로세스를 종료하는 명령으로 대체하지 않는다. 제출 확정 후에는 목표가 남아 있어도 AI 작업을 중단한다. [공식 Goal 명령](https://learn.chatgpt.com/docs/developer-commands#set-or-view-a-task-goal-with-goal)

## 3. 스킬과 로컬 도구 점검

Python 3.10+가 있으면 실제 과제 폴더에서 다음을 실행한다. 제공 환경에서 확인한 실행 파일을 사용하며 아래의 `python3`는 Cofa 셸 예다.

```bash
python3 .cofa-kit/scripts/cofa.py doctor --workspace . --check-mcp --check-plugins
```

이 검사는 설치된 스킬의 차이, 합성 CSV를 사용하는 로컬 MCP 프로세스, CLI 플러그인 명령 지원을 확인한다. **Cofa MCP 연결이나 `/goal` 활성화를 검사하는 명령은 아니다.** 스킬 `not_installed`는 직접 읽기 사용에 문제가 없고, `different`이면 사용자 수정일 수 있으므로 덮어쓰지 않는다. 종료코드가 0이 아니면 세부 결과를 읽고 해당 항목만 처리한다.

Python이 없거나 명령 실행이 차단되면 설치를 반복하지 않는다. SKILL.md 직접 읽기와 기존 프로젝트 도구로 계속한다. 플랫폼의 Python·Codex·인증·감독 설정을 교체하지 않는다.

## 4. MCP 설정 준비와 실제 연결을 구분

현재 제공되는 MCP 도구 목록을 먼저 확인한다. 이미 연결·호출 확인된 서버는 유지한다. 요청에 포함된 기본 후보는 로컬 `cofa_local`과 공개 문서용 Context7·Microsoft Learn·DeepWiki·OpenAI Docs다. 준비한 서버를 매 작업에 모두 호출하지 않는다.

설정이 필요하고 Python을 사용할 수 있으면 아래 명령으로 **현재 환경의 경로가 반영된 JSON**을 만든다. Windows 개발 PC의 경로를 Cofa 설정에 복사하지 않는다.

```bash
python3 .cofa-kit/scripts/install.py --workspace . --mcp-json --mcp-preset context7 --mcp-preset microsoft-learn --mcp-preset deepwiki --mcp-preset openai-docs
```

생성 결과는 `mcpServers` 아래 서버 5개이며 명령 실행만으로 설정 저장·네트워크 연결·스킬 설치가 되지는 않는다.

**Cofa MCP 탭 경로:** 추가할 항목을 JSON 코드블록 하나로 보여 주고, 참가자가 기존 `mcpServers`에 서버 항목을 합쳐 저장하게 한다. `mcpServers` 안에 또 `mcpServers`를 넣지 않는다. 기존 전체 설정을 읽지 못했다면 출력이 전체 교체본이 아니라 추가 후보임을 분명히 한다. 같은 이름의 기존 서버가 다르면 덮어쓰지 말고 충돌을 알린다. 설정 화면을 자동 조작하지 않는다.

참가자가 기존 설정의 로컬 파일 경로를 제공했다면 위 명령에 `--merge-mcp 실제경로`를 붙여 병합을 검증할 수 있다. 원본은 유지하고 출력으로 덮어쓰지 않는다. 키·토큰이 포함된 기존 설정 전체를 대화에 재출력하지 말고 필요한 추가 항목만 보여 준다. 개인 인증 파일·플랫폼 관리 설정을 찾아 읽을 필요는 없다.

제공 환경이 CLI 등록을 명시적으로 지원하고 그 경로가 선택됐다면 [EXTENSIONS.md](../docs/EXTENSIONS.md)의 해당 명령을 사용한다. MCP 탭과 CLI 등록을 동시에 실행하거나, 탭 차단을 우회하는 경로로 CLI를 쓰지 않는다. Python이 없으면 EXTENSIONS의 공식 URL로 원격 서버 항목만 준비할 수 있으나 `cofa_local`은 준비 완료로 표시하지 않는다.

저장 전에는 `JSON 준비 / 화면 저장 필요`, 저장 뒤 도구가 안 보이면 `설정 저장 확인 / 현재 대화에서 호출 미확인`으로 보고한다. 참가자가 “저장했어”라고 하면 **같은 작업을 이어가며 실제 도구 목록을 다시 확인**한다. 재연결·새 세션이 필요하면 현재 작업·목표·기록을 보존하고 제공 환경의 안내만 따른다. 설정 대기 중에도 로컬 파일 작업은 계속할 수 있다.

### 연결 확인에 사용할 공개·합성 입력

실제 도구가 보이고 시간 여유가 있을 때 새로 연결한 서버만 한 번 확인한다. 아래는 도구 이름을 추정해 호출하라는 뜻이 아니다. 현재 도구 스키마에서 지원되는 기능·입력을 확인한다.

| 서버 | 확인 방법 | 확인하지 않은 범위 |
| --- | --- | --- |
| cofa_local | 키트의 `examples/defects.csv`를 `profile_csv`로 요약 | 실제 과제 CSV의 의미·계산 정확성 |
| context7 | 공개 React 라이브러리 식별 질의 | 모든 문서 도구·영구 무인증 이용 |
| microsoft_learn | 공개 Python 가상환경 문서 검색 | 클라우드 계정 연결·리소스 조작 |
| deepwiki | 공개 `python/cpython` 저장소 문서 구조 읽기 | 외부 AI에 시험 답안 생성 요청 |
| openai_docs | 공개 Codex MCP 문서 검색 | Cofa의 실제 설정·운영 규칙 |

원격 질의에는 문제·코드·데이터·로그·접속 정보를 넣지 않는다. 연결 상태와 실제 호출 성공을 나눠 기록하며 인증·사용량·통신 오류는 해당 상태로 표시한다. 키 발급·개인 로그인·프록시 우회·무한 재시도를 하지 않는다. 검증이 끝난 도구는 SCENARIO의 선택 기준에 따라 필요한 작업에만 쓴다.

## 5. 지원되는 키트 플러그인 설치

통합 요청에는 **이 공개 키트 플러그인의 설치 요청**이 포함된다. 별도의 설치 승인을 반복해서 묻지 않는다. 실제 실행 권한 창이나 추가 계정 인증은 제공 환경의 절차를 따른다. 다른 임의의 플러그인까지 설치하는 요청으로 확대하지 않는다.

`doctor`의 플러그인 상태가 `supported`면 현재 설치 목록을 확인한다. 이미 설치돼 있거나 같은 이름의 스킬 복사본이 있으면 중복 설치하지 않는다. 기존 설치본이 다를 때는 삭제·강제 교체 없이 최신 키트의 SKILL.md를 직접 읽고 차이를 알린다. marketplace 이름이 다른 출처로 등록돼 있어도 자동 교체하지 않는다.

기존 충돌·중복이 없고 설치가 필요하면 일반 터미널에서 실행한다.

```bash
codex plugin list --json
codex plugin marketplace add ./.cofa-kit
codex plugin add cofa-ready-kit@cofa-ready
codex plugin list --json
```

앞의 목록 확인 결과를 읽은 뒤 다음 명령으로 진행하며 하나가 실패하면 뒤의 성공을 가정하지 않는다. 설치 목록·설치된 스킬 경로·현재 세션의 사용 가능 상태를 구분한다. 새 세션에서 로드되는 환경이면 작업 대화를 지우거나 즉시 재시작하지 말고 파일 직접 읽기로 계속한다. 플러그인 설치만으로 외부 MCP 4개까지 연결됐다고 보고하지 않는다.

`unavailable`·`failed`이면 사유만 알리고 스킬 직접 읽기와 이미 연결된 MCP로 진행한다. 플러그인과 `scripts/install.py`의 스킬 복사 설치를 함께 실행하지 않는다.

## 6. 준비 결과를 짧게 보고하고 작업을 계속

다음 다섯 항목에 **실제 관찰한 상태와 남은 한 가지 조치**만 보고한다. 설정 보고로 작업을 끝내지 않는다.

- Goal: 실제 활성화 확인 / 목표 지침만 적용 / 미확인.
- 스킬: 읽은 스킬·설치본 상태. 읽기와 등록은 구분.
- MCP: 서버별 JSON 준비 / 화면 저장 대기 / 도구 표시 / 실제 호출 성공 / 실패.
- 플러그인: 지원 확인 / 설치 확인 / 현재 세션 로드 미확인 / 중복 생략 / 미지원.
- 시간: 참가자가 전달한 값·개선 중단 시각 또는 아직 필요한 시간 정보.

이어서 실제 요구·필수 제출물·실무자에게 물을 중요한 질문을 짧게 정리하고, 가능한 구현 → 관련 검사 → 실패 수정 → 회귀 확인을 계속한다. Browser의 핵심 동작은 참가자가 직접 확인하며, 피드백을 같은 대화에서 받아 반영한다. 각 작업 묶음이 끝나면 한 일·이유·방법·실제 확인·남은 일을 쉬운 말로 짧게 설명한다.

시간을 소진하려고 수정하거나 근거 없이 같은 검사를 반복하지 않는다. 개선 중단 시각이면 최종 관련 검사·필수 문서·저장·필요한 용량 점검과 제출 안내로 전환한다. AI는 제출 버튼을 조작하지 않으며, 제출 확정 뒤에는 Goal·스킬·MCP·플러그인 작업을 모두 중단한다.
