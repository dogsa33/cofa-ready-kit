# 필요한 스킬·MCP만 점검하기

제출 확정 전, 도구 준비를 요청받았거나 스킬 탐색·MCP 호출에 실제 문제가 있을 때 사용한다. 먼저 현재 클라이언트에서 보이는 도구와 실제 키트 경로를 확인한다. 이름만 보고 연결됐거나 사용했다고 말하지 않는다.

1. 현재 과제에 필요한 능력을 확인한다. 기본 구현·설명은 파일 읽기와 기존 터미널이면 충분하다. CSV가 없으면 분석 MCP는 추가하지 않는다.
2. 키트의 Python 3.10+ CLI를 사용할 수 있으면 아래 선택형 검사를 실행한다. `.cofa-kit`은 일반적인 다운로드 위치의 예이며 실제 경로가 다르면 바꾼다.

   ```bash
   python3 .cofa-kit/scripts/cofa.py doctor --workspace . --check-mcp
   ```

3. `kit.skills`의 `current`는 배포 파일과 같음, `not_installed`는 선택형 설치가 없음, `different`는 내용 차이, `incomplete`는 배포 파일 누락이다. 차이만으로 구버전이라고 단정하지 않는다. 사용자 수정일 수 있으므로 기존 설치본을 보존하고 응답에 표시된 `source`의 SKILL.md를 직접 읽는다. 참조 파일도 함께 비교하되 사용자 추가 파일은 건드리지 않는다.
4. `kit.local_mcp.status: passed`는 임시 합성 CSV로 로컬 서버 기동·도구 목록·실제 분석 호출을 확인한 결과다. 실제 Cofa 연결·자동 선택·과제 성공은 별도다. 현재 클라이언트에서 도구가 보이는지 확인하고, 필요할 때 허용된 자료로 실제 호출 결과를 확인한다.
5. 실패하면 원인과 CLI 대안을 짧게 알리고 가능한 과제 작업을 계속한다. 같은 실패를 반복 호출하거나 권한·인증·전역 설정을 바꿔 우회하지 않는다. 외부 MCP·플러그인은 실제로 필요한 기능이 없고 참가자가 요청한 경우에만, 제공 환경의 규칙과 공식 설정을 확인해 준비한다.

검사는 스킬·설정을 설치하거나 수정하지 않고 원격 서버에 접속하지 않는다. 공개 OpenAI Docs 서버도 연결이 허용되고 참가자가 선택한 경우에만 일반 공개 기술 질의에 사용한다. 문제·코드·데이터·로그를 원격 질의에 넣지 않는다.

끝에는 `필요한 도구 / 실제 확인 / 실패·미확인 / 다음 방법`을 쉬운 말로 요약한다. 불필요한 도구를 추가하지 않은 이유도 한 문장으로 설명할 수 있다.
